# SSH 키 확인 결과

## 🔍 확인된 사항

### 현재 있는 키
- ✅ `~/.ssh/id_ed25519` - 일반 SSH 키
- ✅ `~/.ssh/id_ed25519.pub` - 공개 키
- ❌ `.pem` 파일 없음 (Downloads 폴더에도 없음)

### 문제
- EC2 인스턴스 접속에는 **키 페어 파일(.pem)**이 필요합니다
- 현재 가지고 있는 `id_ed25519`는 EC2 인스턴스와 연결되어 있지 않을 수 있습니다

---

## 🔑 해결 방법

### 방법 1: EC2 콘솔에서 키 페어 확인

**EC2 콘솔에서 확인:**
1. EC2 콘솔 → 인스턴스
2. `tour_stream` 인스턴스 선택
3. 하단 "세부 정보" 탭에서 **"키 페어 이름"** 확인
   - 또는 "보안" 탭에서 확인

**확인할 것:**
- 키 페어 이름: `_________________`

### 방법 2: 키 페어 파일 찾기

**다른 위치 확인:**
```bash
# 전체 시스템에서 .pem 파일 찾기
find ~ -name "*.pem" 2>/dev/null

# 또는 특정 이름으로 찾기
find ~ -name "*tour*" -name "*.pem" 2>/dev/null
find ~ -name "*stream*" -name "*.pem" 2>/dev/null
```

### 방법 3: 새 키 페어 생성 (키 페어 파일이 없으면)

**EC2 콘솔에서:**
1. EC2 → 키 페어
2. "키 페어 생성" 클릭
3. 이름 입력: `tourstream-api-key`
4. 키 페어 타입: `RSA`
5. 개인 키 파일 형식: `.pem`
6. "키 페어 생성" 클릭
7. **중요**: 자동으로 다운로드됨
8. 다운로드된 파일을 `~/.ssh/`로 이동

**또는 인스턴스에 키 페어 추가:**
- 기존 인스턴스에는 키 페어를 나중에 추가할 수 없습니다
- 새 인스턴스를 만들거나, 다른 방법으로 접속해야 합니다

---

## 🚀 대안: EC2 Systems Manager Session Manager 사용

**키 파일 없이 접속하는 방법:**

1. **IAM 역할 확인**
   - 인스턴스에 `codedeploy-role`이 이미 설정되어 있음
   - SSM(Session Manager) 권한이 있는지 확인 필요

2. **AWS CLI로 접속**
   ```bash
   aws ssm start-session --target i-0157298d8bd0aa708
   ```

**장점:**
- 키 파일 불필요
- 더 안전함
- 포트 22 열 필요 없음

**단점:**
- IAM 권한 설정 필요
- AWS CLI 필요
