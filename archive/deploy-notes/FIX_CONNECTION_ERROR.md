# SSH 연결 오류 해결하기

## ❌ 오류 내용

```
Failed to connect to your instance
Error establishing SSH connection to your instance.
```

**원인:**
- 보안 그룹에서 SSH 포트(22번)가 열려있지 않음
- 또는 다른 네트워크 문제

---

## 🔧 해결 방법

### 방법 1: Session Manager 사용 (가장 간단!)

**EC2 Instance Connect가 안 되면 Session Manager를 사용하세요:**

1. **같은 "연결" 화면에서**
2. **"SSM Session Manager" 탭 클릭**
3. **"연결" 버튼 클릭**

**장점:**
- SSH 포트(22번) 불필요
- 보안 그룹 설정 불필요
- 키 파일 불필요
- 더 안전함

---

### 방법 2: 보안 그룹 수정 (SSH 포트 열기)

**EC2 콘솔에서:**

1. **인스턴스 선택** (`tour_stream`)
2. **하단 "보안" 탭 클릭**
3. **보안 그룹 이름 클릭** (예: `sg-021c2479c7157707c`)
4. **"인바운드 규칙" 탭 클릭**
5. **"규칙 편집" 클릭**
6. **규칙 추가:**
   - 유형: `SSH`
   - 프로토콜: `TCP`
   - 포트 범위: `22`
   - 소스: `내 IP` (또는 `0.0.0.0/0` - 모든 IP, 보안상 권장하지 않음)
7. **"규칙 저장" 클릭**

**주의:**
- `0.0.0.0/0`은 모든 IP에서 접속 가능 (보안 위험)
- 가능하면 "내 IP" 선택 권장

---

## 🎯 추천: Session Manager 사용

**가장 간단하고 안전한 방법입니다!**

### 단계:

1. **EC2 콘솔 → 인스턴스 → 연결**
2. **"SSM Session Manager" 탭 선택**
3. **"연결" 버튼 클릭**

**이 방법이 안 되면:**
- IAM 권한 확인 필요
- 또는 보안 그룹 수정

---

## 📋 현재 보안 그룹 확인

**확인할 것:**
- 보안 그룹 이름: `sg-021c2479c7157707c (default)`
- 인바운드 규칙에 SSH(22번 포트)가 있는지

**없으면 추가해야 합니다.**

## 🆘 여전히 안 되면

**Session Manager도 안 되면:**
- IAM 권한 확인 필요
- `codedeploy-role`에 SSM 권한이 있는지 확인

**어떤 방법을 시도했는지 알려주세요:**
- "Session Manager 탭을 클릭했어요"
- "보안 그룹을 수정했어요"
- "둘 다 안 돼요"

상황을 알려주시면 더 정확히 도와드리겠습니다!
